
# 使用说明

## 首次配置

1. 安装并登录本机 Codex，确认可以正常使用。
2. 在仓库根目录运行 `python scripts/setup_config.py --workspace "自己的工作目录"`。
3. 按 README 的 `login` 命令完成扫码，打开管理界面。
4. 接管一条会话或新建并接管，再启动连接。

默认私有配置：`~/.codex-wechat-session-manager/config.json`；`~` 表示当前用户目录。支持 `--config` 或环境变量 `CODEX_WECHAT_CONFIG` 指定其他配置文件。

登录如果返回 `login_user_id`，成功接管会话时会将其加入允许列表。若未返回，用 CLI 运行 `python src/bridge_runtime.py run --config "配置文件完整路径"`，从微信发送 `/id` 获取 ID，再停止此 CLI，将该 ID 填入本地 `allow_user_ids`，最后启动管理界面。不要同时运行两个消息接收程序。

## 三个按钮的区别

| 按钮 | 作用 |
| --- | --- |
| 启动连接 | 开始接收微信消息并转发到已接管的 Codex 会话 |
| 停止连接 | 停止接收新消息，完成已经收到的批次；仍持有会话 |
| 取消接管 | 在连接停止后关闭本程序的后台、释放会话，保留默认会话配置 |

停止连接可能需要等待当前长轮询返回或已收到的消息处理完成，不能将点击按钮理解为立刻中断任务。

## 文件

微信附件会下载到配置的 `download_dir`；未设置则放到工作目录中的“微信收到的文件”。同名文件会追加时间，避免覆盖。

可直接发送微信指令 `/sendfile C:\Projects\demo\result.zip`，或由 Codex 最终回复中的 `[SEND_FILE: 文件完整路径]` 触发发送。

直接发文件指令允许读取当前 Windows 账号可读的本机路径，不会单独限制在 Codex 工作目录内。仅授权自己信任的联系人。完整工程建议用开发软件归档或压缩成 ZIP，保留目录结构和依赖。

当前没有文件发送失败后的持久重发队列。失败会显示日志或返回错误，需重新发送。

## 常见状态

- **其他进程占用**：另一程序正在持有会话写入权，需退出持有该会话的程序再接管。
- **微信收消息超时**：会自动重试；单次空闲长轮询超时不代表登录必然失效。
- **HTTP 401/403**：检查本机凭据和登录状态，必要时重新扫码。
- **配置被其他程序修改**：本次提交会停止，避免覆盖外部修改；先关闭重复运行的程序。

`config.json`、状态、备份和日志均为运行数据，不要上传 GitHub。尤其备份也可能包含凭据。样例配置可公开。
